# 需求规格说明书 (SRS)

> 项目名称：Go2 四足机器人导航系统 (slam_navx86)
> 版本：v1.0
> 日期：2026-07-23

---

## 1. 引言

### 1.1 编写目的

本文档定义 Go2 四足机器人导航系统的功能需求与非功能需求，作为设计、开发、测试和验收的依据。

### 1.2 适用范围

适用于 Go2 四足机器人在室内/室外结构化环境中的自主导航场景，包括建图、定位、路径规划、运动控制。

### 1.3 术语定义

| 术语 | 说明 |
|------|------|
| SLAM | 同时定位与建图 (Simultaneous Localization and Mapping) |
| NDT | 正态分布变换 (Normal Distributions Transform)，用于点云配准 |
| TEB | 时间弹性带 (Timed Elastic Band)，局部路径规划算法 |
| STVL | 时空体素层 (Spatio-Temporal Voxel Layer)，3D障碍物感知 |
| ROS | 机器人操作系统 (Robot Operating System) |
| UKF | 无迹卡尔曼滤波 (Unscented Kalman Filter) |
| PCD | 点云数据文件 (Point Cloud Data) |
| PGM | 便携灰度图 (Portable Gray Map)，2D地图格式 |

---

## 2. 总体描述

### 2.1 系统目标

构建一套具备以下能力的四足机器人导航系统：
- 激光雷达建图（3D点云 → 2D栅格地图）
- 基于先验地图的实时定位
- 单点/多点自主导航与避障
- Web端远程监控与操控

### 2.2 用户角色

| 角色 | 权限说明 |
|------|----------|
| 管理员 (admin) | 全部功能：用户管理、地图管理、导航控制、系统配置 |
| 操作员 (operator) | 导航控制、地图查看、参数调节、建图操作 |

### 2.3 运行环境

| 项目 | 要求 |
|------|------|
| 机器人端系统 | Ubuntu 20.04 + ROS Noetic |
| 激光雷达 | Livox MID-360 |
| 机器人平台 | Unitree Go2 四足机器人 |
| 计算平台 | NVIDIA Jetson / x86工控机 |
| Node.js | ≥ 20.19.0 |
| Python | 3.8+ |

## 3. 功能需求

### 3.1 建图模块 (FR-MAP)

| 编号 | 需求描述 | 优先级 |
|------|----------|--------|
| FR-MAP-01 | 启动激光雷达建图，实时生成 3D 点云地图 | 高 |
| FR-MAP-02 | 建图过程中实时显示机器人轨迹和点云 | 高 |
| FR-MAP-03 | 停止建图时自动保存 PCD 点云文件 | 高 |
| FR-MAP-04 | 将 3D 点云地图转换为 2D 栅格地图（PGM+YAML） | 高 |
| FR-MAP-05 | 在 Web 端地图编辑器中对栅格地图进行编辑（擦除/绘制） | 中 |

### 3.2 定位模块 (FR-LOC)

| 编号 | 需求描述 | 优先级 |
|------|----------|--------|
| FR-LOC-01 | 基于先验 PCD 地图进行 NDT 实时定位 | 高 |
| FR-LOC-02 | 定位结果通过 TF 发布 map→base_link 变换 | 高 |
| FR-LOC-03 | 支持全局重定位（在未知初始位置时自动恢复定位） | 高 |
| FR-LOC-04 | 从 Web 端手动设置初始位姿 (2D Pose Estimate) | 中 |
| FR-LOC-05 | 显示定位状态（就绪/仅TF/丢失） | 中 |

### 3.3 导航模块 (FR-NAV)

| 编号 | 需求描述 | 优先级 |
|------|----------|--------|
| FR-NAV-01 | 单点导航：在 Web 地图上点击目标点，机器人自主前往 | 高 |
| FR-NAV-02 | 多点导航：预设导航点序列，机器人按顺序依次到达 | 高 |
| FR-NAV-03 | 实时避障：基于激光雷达点云的动态障碍物检测与规避 | 高 |
| FR-NAV-04 | 导航状态实时反馈（运动中/阻塞/到达/对齐中） | 高 |
| FR-NAV-05 | 支持暂停/继续/停止导航 | 高 |
| FR-NAV-06 | 显示全局路径和局部路径 | 中 |
| FR-NAV-07 | 导航目标点拖拽设置（位置+朝向） | 中 |
### 3.4 地图管理模块 (FR-MGR)

| 编号 | 需求描述 | 优先级 |
|------|----------|--------|
| FR-MGR-01 | 多张地图的保存、切换、删除、重命名 | 高 |
| FR-MGR-02 | 地图导出为 ZIP 文件（含 PGM+YAML+PCD） | 中 |
| FR-MGR-03 | 支持导入外部 PGM 地图文件 | 中 |
| FR-MGR-04 | 虚拟障碍物管理（矩形/圆形/多边形） | 低 |

### 3.5 设备控制模块 (FR-CTL)

| 编号 | 需求描述 | 优先级 |
|------|----------|--------|
| FR-CTL-01 | 激光雷达启动/停止 | 高 |
| FR-CTL-02 | 运动控制启动/停止 | 高 |
| FR-CTL-03 | 手动遥控：线速度/角速度控制 | 中 |

### 3.6 用户管理模块 (FR-USER)

| 编号 | 需求描述 | 优先级 |
|------|----------|--------|
| FR-USER-01 | 用户登录认证（JWT Token） | 高 |
| FR-USER-02 | 管理员创建/删除用户 | 中 |
| FR-USER-03 | 基于角色的访问控制 | 中 |

### 3.7 导航参数调节模块 (FR-PARAM)

| 编号 | 需求描述 | 优先级 |
|------|----------|--------|
| FR-PARAM-01 | Web 端调节 TEB 到达容差 | 中 |
| FR-PARAM-02 | Web 端调节障碍物检测范围、高度 | 中 |
| FR-PARAM-03 | Web 端调节膨胀半径、代价衰减 | 中 |
| FR-PARAM-04 | 参数修改持久化到 YAML 配置文件 | 中 |

## 4. 非功能需求

### 4.1 性能需求

| 编号 | 需求描述 | 指标 |
|------|----------|------|
| NFR-PERF-01 | 定位更新频率 | ≥ 10 Hz |
| NFR-PERF-02 | 导航控制频率 | ≥ 10 Hz |
| NFR-PERF-03 | 从点击目标到开始移动 | ≤ 5 秒 |
| NFR-PERF-04 | Web 端遥测刷新频率 | 5 Hz |
| NFR-PERF-05 | 地图加载时间（40M栅格） | ≤ 10 秒 |

### 4.2 可靠性需求

| 编号 | 需求描述 |
|------|----------|
| NFR-REL-01 | 定位丢失后支持全局重定位恢复 |
| NFR-REL-03 | 系统组件异常退出后 Gateway 可重新拉起 |
| NFR-REL-04 | 地图切换后自动加载对应 PCD 并发布初始位姿 |

### 4.3 可用性需求

| 编号 | 需求描述 |
|------|----------|
| NFR-USE-01 | Web 界面支持桌面端浏览器（Chrome/Firefox/Edge） |
| NFR-USE-02 | 地图支持拖拽、缩放、旋转交互 |
| NFR-USE-03 | 建图完成后自动提示保存 |

## 5. 系统边界与接口

### 5.1 外部接口

| 接口 | 说明 |
|------|------|
| Livox 雷达驱动 | 发布 `/livox/lidar` 点云话题 |
| Go2 SDK | 接收 `/cmd_vel` 控制指令，提供 `/go2/sport_cmd` 状态指令 |

### 5.2 内部接口

| 接口 | 说明 |
|------|------|
| Gateway ↔ ROS | 通过 rosbridge WebSocket 协议通信 |
| Web 前端 ↔ Gateway | HTTP REST API + WebSocket 遥测推送 |
| Gateway → move_base | 发布 `/move_base_simple/goal` 导航目标 |

## 6. 约束与假设

### 6.1 技术约束

- 激光雷达必须为 Livox MID-360 或兼容型号
- 地面需为平面或缓坡（四足不具备悬挂系统）
- 需要先建图才能导航（需要 PCD 点云地图）
- ROS 环境需安装 navigation、teb_local_planner、hdl_localization 等包

### 6.2 假设条件

- 环境中存在足够的几何特征供 NDT 配准
- 导航过程中激光雷达正常工作
- 网络连接稳定（Web 前端与 Gateway 之间）
- 机器人电池电量充足
